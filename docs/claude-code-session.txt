❯ what is bse throttling and what purpose it serve                              

⏺ BSE is the Bombay Stock Exchange, one of India's two main exchanges. Companies
  file their announcements with it, and each filing is stored as a PDF on its
  website.

  Throttling (also called rate limiting) is when a website deliberately refuses
  requests that arrive too fast from the same visitor. It isn't an error in
  FINN's code; it's the website saying "slow down".

  What purpose it serves (for BSE)

  1. Protects their servers. Thousands of traders and bots hit BSE during
     results season. Without limits, a few aggressive scrapers could slow the
     site for everyone.
  2. Discourages bulk downloading. BSE sells official data feeds to businesses.
     Free website access is meant for people reading filings, not machines
     copying everything.
  3. Fairness: no single user hogs the capacity.
  4. Cost control, since serving large PDFs uses bandwidth they pay for.

  What we saw

  - When FINN requested several filing PDFs in quick succession, BSE sometimes
    answered "406 Not Acceptable" instead of the PDF.
  - The same link worked fine on its own or after a pause. That's the giveaway
    that it's speed-based, not a broken link.
  - BSE doesn't publish its exact limits, so the "about one request every 2.5
    seconds" figure is my estimate from testing, not an official number.

  How FINN handles it

  FINN is designed to stay polite rather than get around the limit:
  - Pacing: at most one BSE request every 2.5 seconds.
  - Caching forever: a filing never changes once published, so FINN downloads
    each PDF once and never again. Re-runs cost BSE nothing.
  - Honest identification: every request says it's the FINN prototype, rather
    than pretending to be a browser.
  - The planned fix: go straight to the PDF's final address, since the link
    screener gives is a redirect. That halves the requests per filing. When BSE
    says slow down, FINN will also wait longer before retrying.

  The fix doesn't try to trick BSE. It makes fewer requests and backs off when
  asked, so failed downloads should mostly disappear.
